# Whoppah — OctoPrint pen plotter plugin

[English version](README.md)

> — Dad, can we have a pen plotter at home?<br>
> — **W**e **H**ave **O**ur **P**en **P**lotter **A**t **H**ome (WHOPPAH)

Веб-приложение для пен-плоттера на основе 3D-принтера под управлением OctoPrint.
Протестировано на Elegoo Neptune 3 Pro (Marlin) и OctoPrint 1.11.

Рисунок (SVG, фото в одном из стилей линий или текст) → раскладка на листе → G-code для пера → скачивание или отправка в OctoPrint.

Чистый JavaScript (ES modules), без сборки и без npm-зависимостей.

## Запуск

```sh
cd plotter
python3 -m http.server 8000
```

Открыть <http://localhost:8000/>. С `file://` не работает (ES modules), нужен http-сервер. Firefox и Chromium последних версий.

### GitHub Pages

Standalone-приложение — это просто статические файлы, поэтому оно работает и с GitHub Pages (или любого статического хостинга) без локального сервера:

- HTTPS-страница может обращаться к OctoPrint по `http://localhost:5000`: localhost браузеры считают доверенным (свежий Chrome может один раз спросить разрешение на доступ к локальной сети).
- OctoPrint по адресу в локальной сети по обычному HTTP (`http://octopi.local`, `http://192.168.…`) блокируется как смешанное содержимое (mixed content): включите HTTPS у OctoPrint или используйте [плагин OctoPrint](#плагин-octoprint).
- CORS в OctoPrint должен разрешать адрес Pages (`https://<user>.github.io`), см. [Настройка OctoPrint](#настройка-octoprint).
- Настройки хранятся в localStorage этого адреса, отдельно от `http://localhost:8000`: переносите их экспортом/импортом настроек. Ключ API остаётся в браузере (в файл экспорта он не попадает, его вводят заново).

## Плагин OctoPrint

Приложение можно отдавать самим OctoPrint 1.11 полноэкранной страницей `/plugin/plotter/`: без отдельного сервера, API-ключа и CORS, с общими для всех устройств настройками. Standalone-режим (выше) продолжает работать параллельно.

**Режимы.** При запуске приложение читает `env.json` рядом со страницей: статический `{"mode":"standalone"}` — REST с API-ключом и настройки в браузере; динамический `env.json` плагина — авторизация сессией OctoPrint (заголовок `X-CSRF-Token`) и настройки на сервере. Код вкладок и ядра от режима не зависит; в режиме плагина адрес и ключ не показываются, в шапке есть ссылка «← OctoPrint».

**Установка.**

```sh
python3 tools/build_plugin.py        # копирует index.html, src/, vendor/ в пакет плагина и собирает dist/OctoPrint-Plotter-<версия>.zip
```

OctoPrint → Settings → Plugin Manager → «Get More…» → «… from an uploaded file» → выбрать zip → перезапустить OctoPrint. В верхней панели появится ссылка «Plotter». Версия zip берётся из git: MAJOR.MINOR — из `octoprint-plugin/octoprint_plotter/_version.py`, PATCH — число коммитов, поэтому каждый коммит даёт версию выше и новый zip ставится поверх старого; при незакоммиченных правках добавляется `.post<время UTC>`. Сборка не меняет файлы в репозитории; `--version X.Y.Z` задаёт версию явно. Обновление — тем же способом с новым zip (после перезапуска браузер сам перепроверяет файлы: страница и статика отдаются с `Cache-Control: no-cache` и ETag). Удаление — в Plugin Manager. Версия — `octoprint-plugin/octoprint_plotter/_version.py` (или `--version X.Y.Z` при сборке).

**Права и хранение настроек.**

- Страница и служебные адреса доступны только вошедшим пользователям (без входа — переход на вход OctoPrint и возврат в приложение).
- Профили машины (с активным) и калибровка общие для всех; параметры задания и пресеты — свои у каждого пользователя. Смена профиля на другом устройстве подхватывается при следующем опросе (5 с).
- Любая запись профилей — значения, стол, создание, дублирование, переименование, удаление **и выбор активного** — требует права **«Plotter: Machine profile»** (`PLUGIN_PLOTTER_MACHINE_PROFILE`): по умолчанию есть у группы администраторов; выдаётся в Settings → Access Control (пользователю или группе). Без права профили показываются только для чтения.
- Запись калибровки требует штатного права OctoPrint **Control**. Печать, загрузка и пауза проверяются правами OctoPrint (Print, File Upload, Control); при отказе показывается «нет права: …».
- Раздел не больше 1 МБ; неизвестные разделы сервер отклоняет.

**Захват калибровки и пульт.** Подведите перо штатной вкладкой Control, затем на вкладке «Печать» нажмите «Угол здесь» (с учётом смещения пера от угла листа) или «Касание здесь»; положение читается командами `M118`/`M400`/`M114` (во время печати недоступно). «Угол верен» / «Касание верно» подтверждают часть без изменения значений. После хоминга (`G28`) или переподключения принтера приложение показывает «калибровка могла устареть», а печать требует подтверждения. Нужны право Control и прошивка, отвечающая на `M118`.

Те же кнопки есть и в standalone, когда на связи поток принтера: калибровка лежит в браузере, версии координат — в памяти потока, поэтому после перезагрузки страницы обе части считаются устаревшими до нового захвата или «Угол верен» / «Касание верно». Пока поток не видел `G28` (с момента подключения к принтеру; Home по осям учитывается отдельно для XY и Z), захват и пульт отключены с подсказкой «Home не выполнен — сделайте Home до установки пера»; `G28` приложение само не шлёт — только кнопка «Home (G28)» рядом с подсказкой, после подтверждения, что перо снято или поднято выше сопла; если Home сделан до открытия страницы (с пером `G28` опасен), кнопка «Home уже сделан» с подтверждением снимает защиту до ближайшего переподключения, версии координат она не меняет. Пульт перемещения (X±/Y±/Z±, шаг 0.1/1/10 мм, оба режима) читает положение перед каждым шагом, не выходит за пределы осей профиля, а Z — ниже касания больше чем на 2 мм; если стол измерен, а перо может быть опущено (Z неизвестен или ниже касание + зазор), X/Y не выходят из области печати, а за краем стола Z не ниже касание + зазор.

**Настройки прошивки (standalone, поток на связи).** «Прочитать настройки прошивки» (раздел «Подключение») шлёт `M503` и разбирает `M201`/`M203`/`M204`/`M205`/`M420`: сводка, предупреждения (подачи профиля выше `M203`, затухание сетки ниже касания), «Заполнить ускорения профиля…» по подтверждению. Результат хранится только в памяти, до обрыва потока; пока он есть, оценка времени срезает подачи по `M203` и стартует с рывка `M205` (пометка «с учётом прошивки»). В плагине потока нет — там не доступно.

**Перенос настроек из standalone.** В standalone: «Экспорт в файл» внизу панели настроек; в плагине: «Импорт из файла…». Профили и калибровка при отсутствии прав пропускаются с сообщением, остальное импортируется. Если на сервере у пользователя ещё нет настроек, а в `localStorage` того же адреса (host:port) есть настройки standalone, приложение предложит перенести их само.

За обратным прокси с префиксом (`X-Script-Name`) адреса строятся от `script_root`, приложение открывается по `https://host/octoprint/plugin/plotter/`.

## Настройка OctoPrint

1. В OctoPrint: Settings → API → включить **Enable Cross Origin Resource Sharing (CORS)**.
2. Там же взять **API key** (Settings → API → Application Keys или глобальный ключ).
3. В приложении, вкладка «Печать» → «Подключение»: адрес (`http://localhost:5000` для OctoPrint на этой же машине, по умолчанию; `http://octopi.local` для OctoPi на Raspberry Pi) и ключ; кнопка «Проверить связь».

Без адреса и ключа кнопки отправки неактивны, скачивание G-code работает. Ключ хранится только в localStorage браузера и не попадает в файл экспорта настроек.

## Настройки и калибровка

Все координаты в приложении — **положение головы** (сопла), как на экране OctoPrint; перо смещено относительно него, и приложение учитывает смещение через область пера и угол листа.

**Первая настройка (визард).** Карточка «Готовность к печати» сверху вкладки «Печать» показывает, что должно быть задано: связь (только standalone), область пера, угол листа, касание — готово / не задано / проверить, с кнопкой «Настроить» у пункта и «Пройти настройку» для всего визарда. Визард — модальный диалог по шагам, каждое изменение сохраняется сразу, закрыть можно на любом шаге:

1. **Связь** (standalone): адрес OctoPrint и ключ API, индикатор, «Проверить связь».
2. **Область пера**: профиль машины (принтер + держатель пера) и где кончик пера может рисовать — одним из двух способов (ниже).
3. **Лист**: формат и ориентация; положите лист на стол, затем либо «Подвести перо в угол области» (перо зависает над ближним левым углом области пера — подвиньте угол листа под кончик пера), либо подведите перо пультом в угол листа; затем «Угол листа здесь». «Перо не достаёт до угла листа» хранит смещение пера от угла для такого случая.
4. **Касание**: опускайте Z шагами, пока перо не коснётся бумаги, «Касание здесь»; ширина пера.
5. **Проверка**: список готовности, «Перо вверх», «Обвести рамку» (когда рисунок загружен).

На шагах с перемещением головы есть пульт (шаг 0.1/1/10 мм, X±/Y±/Z±) и защита «Home не выполнен» с кнопкой «Home уже сделан». Без источника положения (нет потока плагина) шаги показывают только поля для чисел.

**Область пера** (активный профиль). Два способа, выбираются переключателем; оба заполняют один и тот же прямоугольник стола профиля:
- **Смещение пера от сопла** `dx, dy` (правее / дальше от себя — положительно; перо ближе к себе, чем сопло, — отрицательный `dy`): стол в координатах головы — номинальный стол (по умолчанию 235×235 мм), сдвинутый на −смещение, дальний угол «по номиналу». Введите числа или подведите кончик пера в любой угол стола, до которого оно достаёт, выберите этот угол и нажмите «Перо здесь»: смещение = угол − положение головы. Пример: перо на 35 мм правее сопла, пределы X-4…234 — перо достаёт 204 мм по X.
- **Крайние положения пера**: ближнее левое и дальнее правое положение кончика пера над столом — «Взять текущее» или числа; хранятся как измеренные углы.
Редактор показывает «Перо достаёт: W × H мм», карту (стол, пределы осей, область пера, лист) и «Перейти» в углы области для проверки на глаз. **Область печати** = пределы осей ∩ стол; область не задана — пределы осей, а проверки «перо на столе» пропускаются с пометкой. Версии координат у стола нет (хоминг не делает его устаревшим).

Раскладка панели настроек:

- Карточка **«Готовность к печати»**, затем **«Задание»** (каждый раз): формат бумаги (свои форматы сохраняются), ориентация, отступ, выравнивание, поворот, «как есть в мм», «Ограничить областью печати»; свёрнутые **«Оптимизация»** (допуски упрощения и слияния) и **«Калибровка — значения»** (угол листа и касание числами, с датой).
- **«Принтер»** (свёрнуто, редко): **профили машины**, редактор области пера, высоты пера как смещения от касания, скорости, пределы осей, ширина пера, `G28`/`M84`, подключение (standalone), экспорт/импорт настроек. Состояние сворачивания запоминается в браузере.
- Карточка калибровки справа: предупреждение «могла устареть» с «Угол верен» / «Касание верно», пульт и «Настроить…».

**Профили машины.** Профиль — «принтер + держатель пера»: до 20 именованных профилей, один активный; «Новый» (значения по умолчанию), «Дублировать», «Переименовать», «Удалить» (не последний; при удалении активного активным становится соседний). Раскладка, G-code, проверки, пульт и оценка времени берут активный профиль; параметры задания, угол листа и касание в профиль не входят и при смене не меняются. Угол и касание зависят от держателя, поэтому после смены профиля обе части помечаются «калибровка могла устареть (сменён профиль машины)», и печать просит подтверждения — до нового захвата, ввода или «Угол верен» / «Касание верно» (возврат к прежнему профилю — снова актуально). Единственный профиль прежних версий при первом запуске становится профилем «Neptune 3 Pro» (standalone — в браузере, плагин — на сервере); старые данные не удаляются.

**«Ограничить областью печати»** (задание, по умолчанию включено, отмечено ⚠): рисунок вписывается (масштаб и выравнивание) в (поле листа − отступы) ∩ (область печати, переведённая в координаты листа через угол); сам лист может выходить за область (предупреждение по сторонам). Выключено: вписывание в лист, как раньше. Если поле минус отступы целиком в области печати, G-code одинаков при включённой и выключенной опции. Перед отправкой рисунок проверяется по области печати независимо от опции: выход за предел оси или за край стола (по сторонам, в мм) — подтверждение.

**«Точка» и «Перейти».** Любая точка в координатах головы (угол листа, положения пера) — один и тот же элемент: X/Y, «Взять текущее», «Перейти». «Перейти» читает положение, поднимает перо до высоты старта, если оно ниже (или неизвестно), переводит по X/Y и при актуальном касании опускает до касание + зазор; точка вне пределов осей — отказ. Защиты и права — как у пульта.

Экспорт/импорт настроек файлом — внизу панели настроек: версия формата 2 (все профили с активным, калибровка, задание, пресеты); файл версии 1 (один профиль) отклоняется с сообщением «старый формат файла настроек не поддерживается». Настройки старой страницы (`neptune-plotter.settings`) переносятся один раз при первом запуске.

**Подсказки к кнопкам.** У каждой кнопки короткая подсказка (ключ словаря `<область>.<кнопка>.hint`): на компьютере — при наведении, на сенсорном экране — знак «?» рядом с кнопкой (текст под кнопкой).

## Вкладки

### Вкладка «SVG»

Перетащите SVG-файл на вкладку или нажмите, чтобы выбрать. Вкладка показывает число линий и точек и размер в мм, если он задан в файле; текстовые элементы и растровые изображения пропускаются с предупреждением (текст сначала переведите в кривые). Рисунок сразу уходит на вкладку «Печать» и импортируется заново при смене поля, отступа или поворота.

### Вкладка «Фото» и стили

Вкладка «Фото» превращает фото в линии: изображение → стек слоёв-стилей, каждый видимый слой становится слоем рисунка. Новый запуск слоя отменяет прежний. Слой получает статус «готово» только по достоверному сигналу завершения; у стилей plotterfun, не проверенных для версии из vendor, результат остаётся промежуточным, и печать — с подтверждением.

**Кадр и «Растворить фон».** «Кадр» на превью показывает всё фото с рамкой: угол или сторону тянут, чтобы изменить размер, внутри — чтобы сдвинуть (мышью или пальцем; масштаб превью в этом режиме выключен). «Рамка» — свободные пропорции или пропорции поля рисунка (поле минус отступы, при повороте — обратная; при включении рамка сразу подгоняется). Слои пересчитываются один раз — когда рамку отпускают; «Сбросить кадр» снова рисует всё фото. Кадр получает всё рабочее разрешение (`rasterize(decoded, workingSize, crop)`), поэтому масштаб бумаги `mmPerPx` и проверка плотности считаются по нему: кадр из половины фото ложится на то же поле вдвое крупнее. «Растворить фон» (сила, размер, мягкость; сила 0 — выключено) — одна настройка для всех слоёв: вне эллипса в середине кадра (100 % — вписан в кадр) изображение плавно (smoothstep по мягкости) уходит в белый (`applyVignette` в `src/styles/prep.js`, применяется к рабочему изображению до любого стиля), и светлые линии исчезают к краям, как в овальном гравированном портрете; изменение пересчитывает слои с той же задержкой, что и параметр слоя. Кадр принадлежит фото: он живёт в модели вкладки (переживает смену языка и пресет), новый файл его сбрасывает, и он не сохраняется — пресет восстанавливается без фото, а кадр одного снимка вырезал бы из другого случайный кусок. «Растворить фон» сохраняется вместе со слоями в пресете вкладки (поле `vignette`; пресет без него выключает растворение).

#### Волнистые линии

Параллельные линии под углом и с шагом (мм на бумаге); каждая линия — волна, у которой с тёмностью полосы растёт амплитуда, частота или обе; в тёмном линия утолщается до 3 или 5 проходов на расстоянии «шаг проходов × ширина пера» (они сливаются в одну толстую линию, внутри штриха перо не поднимается); в светлом ниже порога обрыва линия прерывается (блики короче одного шага её не рвут). Амплитуда ограничена так, чтобы соседние линии наибольшей толщины не касались; «Сдвигать каждую вторую линию на полпериода» ставит соседей в противофазу (выключено — в фазе). Линии выводятся змейкой. Три пресета: тонкие волны, классика (значения по умолчанию), крупно. Значения по умолчанию — предварительные до проверки на бумаге.

Для волнистых линий «Соединять концы штрихом до» (`linkTolMm`, «Оптимизация») ставьте либо 0, либо сознательно чуть больше шага линий: тогда соседние линии змейки соединяются штрихом вдоль края изображения или края светлого участка — быстрее, но переходы видны как контур. Значение меньше шага ничего не соединяет.

#### Гравюра

Линии следуют форме изображения, как в портрете на банкноте. Тон реального фото сначала подготавливается: «Автоуровни» (включены по умолчанию) растягивают диапазон яркости между перцентилями «Автоуровни: отсечка, %» и 100 минус она — у блёклого фото появляются чёрное и белое; «Локальный контраст, %» подмешивает адаптивное выравнивание гистограммы с ограничением контраста (CLAHE, 8 плиток по длинной стороне) — светлое лицо на ярком фоне всё равно получает читаемые полутона.

Поле направлений — сглаженный структурный тензор яркости в двух масштабах: линии идут вдоль линий равного тона (изофот), повёрнутых на «Поворот к изофотам» (90° — поперёк, например вокруг освещённого сбоку цилиндра). «Сглаживание поля» (мм) — размер форм, за которыми идут линии (овал лица, складка ткани); «Мелкие детали, %» — насколько их изгибают детали в масштабе втрое меньше (глаза, нос, пряди волос): 0 % — только крупная форма, 100 % — полностью детали. Очень резкие перепады (силуэт, линия волос) входят в поле ограниченными, поэтому линии рядом с краем не тянутся все вдоль него. Где яркость почти не меняется («Порог плоских областей» — изменение яркости на 1 см бумаги, %), у структуры нет ясного направления или это текстура, а не форма (листва, трава, шум — «Упрощать фон, %»: чем больше, тем больше её уходит к базовому углу), линии плавно переходят к «Базовому углу»; «Следовать форме» 0 % даёт везде прямые параллельные линии. Поле зависит от автоуровней, но не от яркости, контраста, гаммы, инверсии и локального контраста — они меняют только тон.

Линии — равномерно разнесённые линии тока (Jobard–Lefer): расстояние между соседями меняется от «Шага в тёмном» до «Шага в светлом» (оба × «Базовый шаг», мм), линии сходятся не ближе половины этого расстояния и там кончаются; ниже «Обрыва в светлом» линия не рисуется (блик уже примерно двух светлых шагов её прерывает, за ним она продолжается по тому же следу). Первая линия начинается в центре изображения, следующие — рядом с уже проведёнными, поэтому соседние линии рисуются подряд. В тёмном линия утолщается 3 или 5 сливающимися проходами (как у волнистых линий) с «Тонкими концами штрихов», как след резца, но не шире «Макс. заливки в тенях, %» от расстояния до ближайшей другой линии (в тенях остаются тонкие белые линии, а не сплошная заливка); в самых тёмных местах («Порог перекрёстного слоя») поверх рисуется второе семейство тонких линий под «Углом перекрёстного слоя» — в том же слое рисунка (одно перо). Штрихи короче «Мин. длины штриха» или трёх расстояний между линиями отбрасываются (нет мусора из коротких штрихов в текстуре), линия не длиннее «Макс. длины линии». Пресеты: портрет (значения по умолчанию), банкнота (плотные ровные длинные линии, тон толщиной, спокойный фон, без перекрёстного слоя), эскиз (редкие короткие линии, больше деталей, перекрёстный слой в тенях). Значения по умолчанию — предварительные до проверки на бумаге.

Все параметры живые. Статус показывает фазы («Поле направлений», «Линии 45%», «Перекрёстный слой 70%», «Завершение»), основные линии появляются до конца расчёта. Если шаг слишком мал для изображения, размещение останавливается на пределе числа точек, и у слоя рядом с «готово» написано «Слишком много линий — увеличьте шаг».

Для гравюры начинайте с «Соединять концы штрихом до» (`linkTolMm`) 0: концы линий не лежат на одном краю, как у волнистых линий, и соединение рисует заметные штрихи поперёк рисунка.

### Вкладка «Текст»

Вкладка «Текст» (`src/app/tabs/text-tab.js`, модель `src/app/text/text-model.js`) пишет фразу **однолинейным шрифтом**: каждая буква — несколько открытых штрихов по средней линии, перо проходит их один раз, как рука ручкой или линером (без контуров и нажима). Введите текст (можно несколько строк), выберите шрифт (под списком — образец) и задайте: высоту заглавных букв в мм, межбуквенный интервал (% высоты), межстрочный (× высоты, между базовыми линиями), наклон, выравнивание (влево / по центру / вправо относительно самой длинной строки или ширины переноса), ширину строки для переноса по словам (0 — без переноса; слово длиннее строки переносится по буквам) и «Как от руки». Превью следует за каждым изменением; на вкладку «Печать» рисунок уходит только по «В печать». Рисунок в миллиметрах (`unitMm: 1`): опция задания «Как есть в мм» печатает заглавные ровно заданной высоты; вписывание в поле работает как для любого рисунка.

**«Как от руки»** (0–100 %) даёт каждой букве небольшой случайный разброс размера, наклона, поворота, смещения и шага, а строке — плавную волну и наклон базовой линии. Разброс задаётся зерном: тот же текст, параметры и зерно дают те же линии (и после перезагрузки); «Новый вариант» выбирает другое зерно. Сила масштабирует один и тот же рисунок разброса, поэтому ползунок меняет его плавно; 0 % — точно шрифт. Пресеты почерка (аккуратно, естественно, торопливо) меняют только интервал, наклон и «Как от руки». Текст, шрифт, параметры и зерно сохраняются в пресете вкладки.

**Встроенные шрифты** (`src/app/text/fonts/*.json`, во всех латиница, цифры, русский алфавит с Ё, «», —, …): Hershey Script, EMS Felix, EMS Allure (рукописные) и NewStroke (технический гротеск). Свободного однолинейного *рукописного* шрифта с кириллицей не нашлось, поэтому кириллица, буквы Latin-1 и типографские знаки рукописных шрифтов при сборке берутся из NewStroke: под высоту заглавных шрифта, строчные — под его высоту строчных, с наклоном шрифта. Их кириллица — печатный курсив, а не пропись. Знак, которого нет в шрифте, берётся из NewStroke (с примечанием под превью), типографские знаки заменяются простыми (« » → ", — → -, … → ..., № → No, ё → е), остальное рисуется «?» с предупреждением.

**Свои шрифты.** «Добавить шрифт…» принимает однолинейные SVG-шрифты (`<font>` с `<glyph unicode d>`, как у расширения Hershey Text в Inkscape) и файлы Hershey `.jhf` (кодовые точки с 32 по порядку). Контурные шрифты отклоняются: TTF/OTF/WOFF сразу, SVG-шрифт из замкнутых контуров — с сообщением «похоже, это контурный шрифт; пока поддерживаются только однолинейные». Разобранный шрифт (тот же JSON, что у встроенных, обычно десятки КБ) хранится у пользователя: в плагине — в разделе пользователя `fonts` на сервере (не больше 1 МБ со всеми его шрифтами; шрифт, который не влезает или который сервер не принял, остаётся только в этом браузере, сообщение об этом говорит), в standalone — в localStorage браузера. «Удалить шрифт» удаляет выбранный свой шрифт. В файл настроек шрифты не входят.

**Размер и порядок на «Печати».** Текст включает в задании «Как есть, в мм», и буквы получают заданную на вкладке высоту заглавных; чтобы масштабировать текст под поле, галку можно снять. Следующий рисунок из SVG или фото возвращает галку как была (если её не переключали вручную). Текст печатается в порядке чтения и письма (сначала верхняя строка, слева направо, каждый штрих по направлению письма), а не «ближайший от угла».

## Язык интерфейса

Языки: английский (`en`, запасной), русский (`ru`), испанский (`es`), немецкий (`de`) и французский (`fr`).

Какой язык включить (`src/i18n/detect.js`, `src/app/lang.js`), по убыванию приоритета:

1. явный выбор в переключателе языка в шапке страницы (Авто / English / Русский / Español / Deutsch / Français, на всех вкладках, в standalone и в плагине), хранится в `localStorage` (`whoppah.lang`);
2. плагин: язык интерфейса текущего пользователя OctoPrint — `language` в динамическом `env.json` (пользовательская настройка `interface.language`, иначе общий `appearance.defaultLanguage`; «_default» значит «не выбран»);
3. `navigator.languages`: первый поддерживаемый по основной части кода (`ru*` → русский, `de-AT` → немецкий, `es-MX` → испанский, `fr-CA` → французский, `en*` → английский);
4. иначе английский (в том числе для неподдерживаемого языка OctoPrint, например `it`, — тогда смотрится язык браузера).

Язык выбирается при запуске, до построения интерфейса. Переключение в шапке работает **сразу, без перезагрузки страницы**: рисунок, настройки и профили, загруженный SVG-файл, фото со слоями и идущими расчётами, журнал вкладки «Печать», активная вкладка и масштаб предпросмотра остаются. Уже показанные сообщения пересчитываются на новом языке; тексты, полученные раньше от ядра или OctoPrint (предупреждения импорта, журнал, подробности связи), остаются на прежнем языке, пока не появятся заново. Тексты сервера плагина (Python) остаются английскими: приложение показывает их только как подробности ошибки.

### Как добавить источник рисунка

Создать `src/app/tabs/<имя>-tab.js`, экспортировать фабрику объекта `{ id, title, mount(el, ctx), unmount(), dispose?() }` и добавить её в список вкладок в `src/app/main.js`. `mount` может вызываться повторно после `unmount` с тем же `ctx` (смена языка перестраивает представления): модель (загруженные данные, результаты, идущая работа) хранится в фабрике, а не в представлении; `unmount` снимает только подписки и обработчики представления, `dispose` (необязательный) разбирает и модель. Источник получает только `ctx`:

- `ctx.emit(drawing)` — выдать рисунок (`createDrawing` из `core/drawing.js`, координаты «документ»);
- `ctx.presets.load()/save(obj)` — своя область сохранения;
- `ctx.printParams.get()/subscribe(fn)` — только чтение: поле, отступ, поворот, ширина пера.

Вкладка «Печать» не меняется. Промежуточный результат помечается `meta.partial = { reasons: [...] }`.

#### Вкладка «Фото»: устройство

Вкладка «Фото» (`src/app/tabs/photo-tab.js`) — обычный источник: изображение → стек слоёв-стилей → `ctx.emit(drawing)`, каждый видимый слой становится слоем рисунка. Расчёт идёт в воркерах (`src/styles/runner.js`), новый запуск слоя отменяет прежний. Слой получает статус «готово» только по достоверному сигналу завершения; для стилей plotterfun он строится обёрткой `src/styles/plotterfun-host.js` по манифесту `src/styles/plotterfun-completion.json` (модель исполнения каждого стиля: `sync`, `async-handler`, `timer-chain`, `none`). Манифест действует только для коммита из первой строки `vendor/plotterfun/UPSTREAM`; после обновления vendor запустить `python3 tools/audit_plotterfun.py` — непроверенные стили получат `none` (результат остаётся промежуточным, печать — с подтверждением).

**Кадр.** Геометрия рамки — `src/app/photo/crop.js` (чистые функции).

Тексты статуса собственных стилей могут содержать числа: воркер шлёт прогресс как `{ key, params }` (например, `{ key: 'styles.progress.waves', params: { percent: 40 } }` → «Волнистые линии 40%»), обычные строки — ключи словаря или тексты plotterfun.

**Этапы гравюры.** Все параметры живые: ползунки толщины и «Макс. заливка в тенях» пересчитывают только последний этап, ползунки перекрёстного слоя не трогают основные линии, базовый угол, мелкие детали и упрощение фона переиспользуют тензор, локальный контраст — поле. Стиль может приложить такое замечание («Слишком много линий — увеличьте шаг») к итоговому результату: `yield { note: { key, params } }`.

#### Добавить свой стиль

Простой путь: чистая функция `(gray, w, h, params, paper) => lines` (линии — полилинии `Float64Array` в px рабочего изображения) в `src/styles/own/`, запись `'own:<имя>': plain(fn, 'styles.progress.<ключ>')` в таблице `IMPL` файла `src/styles/own/worker.js` и дескриптор в `src/styles/registry.js` (так сделан `crosshatch`).

Стиль с живыми ползунками — генератор этапов (пример — `src/styles/own/waves.js`):

```js
function* mySteps({ gray, w, h, params, paper, cache }) {
  const dark = stage(cache, 'tone', [params.invert, params.gamma], () => toDarkness(gray, params));       // этап с кэшем
  const geo = yield* stageGen(cache, 'geo', [dark, params.spacing], function* () { /* yield progressOf(KEY, f) */ });
  return stage(cache, 'finish', [geo, params.passes], () => /* Float64Array[] */);
}
export const myStyle = (gray, w, h, params, paper) => runToEnd(mySteps({ gray, w, h, params, paper, cache: createCache() }));
```

В `IMPL` он регистрируется как `staged(mySteps)`. Воркер исполняет его драйвером `src/styles/style-driver.js`: квантами по 30 мс (между ними обрабатываются сообщения), прогресс не чаще 200 мс, `yield { partial: lines }` — промежуточный результат, возвращаемое значение — финальный. Параметры с `live: true` идут в работающий воркер; побеждает последнее значение (текущий генератор бросается на ближайшей границе кванта и запускается заново с тем же кэшем этапов, поэтому пересчитываются только этапы с изменившимися зависимостями; брошенный этап ничего не сохраняет). Зависимости этапа сравниваются через `===`; чтобы связать этапы, передайте значение предыдущего этапа как зависимость. Результат должен зависеть только от изображения, параметров и `paper` — живое изменение даёт то же, что новый запуск (это проверяют тесты).

Поля дескриптора сверх `id, name, group, origin, params, adapter, createWorker, spacing`:

- `usesPaper: true` — размерные параметры заданы в мм на бумаге. Запуск получает `paper = { mmPerPx, penWidthMm }` (`mmPerPx` — масштаб «px рабочего изображения → мм», тот же, что в проверке плотности: поле минус отступы с учётом поворота; без параметров печати 0.25 мм/px и перо 0.5 мм); вкладка пересчитывает слой, когда поле, отступ, поворот или ширина пера меняют этот масштаб. Масштаб предполагает, что рисунок заполняет изображение (раскладка вписывает охватывающий прямоугольник рисунка), «Ограничить областью печати» пока не учитывается. `spacing(params, image, paper)` возвращает шаг линий в px для проверки плотности.
- `presets: [{ id, label, params }]` — пресеты стиля: в карточке слоя появляется строка «Пресет» (значения по умолчанию, поверх — значения пресета; слой перезапускается); значения сохраняются в пресете вкладки как обычно.
- у параметра `select` может быть `optionLabel(value)` — показываемый текст варианта (само значение от языка не зависит).

Общие чистые помощники в `src/styles/own/kit/` (без DOM, работают в node-тестах): `params.js` (`paramFactory(prefix)` — ленивые подписи `t('<prefix>.param.<key>')` и подписи вариантов `t('<prefix>.<key>.<value>')`; `presetFactory(prefix)` — `t('<prefix>.preset.<id>')`; `presetValues`, `matchPreset`), `paper.js` (`DEFAULT_PAPER`, `paperOf`, `mmToPx`, `samePaper`), `lines.js` (`lineFamily` — параллельные линии через изображение, обрезанные им, `clipLine`, `arcLengths`, `dropShort`), `stroke.js` (`thicknessProfile`, `thicken` — толщина линии 1/3/5 близкими проходами внутри одной непрерывной полилинии с сужающимися «линзами», `endTaperPx` — тонкие концы штриха), `order.js` (`orientChain`, `orientGroups` — направления штрихов для коротких переходов, змейка для семейства линий), `stages.js` (`createCache`, `stage`, `stageGen`, `runToEnd`, `progressOf`). Также `toDarkness` (с `gamma`), `boxBlur`, `sampleBilinear` из `src/styles/tone.js` и `simplifyLine` из `src/core/optimize.js`. Все тексты — через `t()`: добавьте ключи `<prefix>.param.*`, вариантов и пресетов в `en.js` и `ru.js`, а стиль — в `OWN_PREFIX` в `tests/i18n.test.js`.

#### Вкладка «Текст»: интерфейс шрифта и пересборка

Интерфейс шрифта: вёрстка (`src/core/text-layout.js`) знает только `StrokeFont` — `{ id, name, capHeight, xHeight, glyphs: Map<кодовая точка, { advance, lines }> }` в единицах шрифта, базовая линия y = 0, Y вниз (`src/core/stroke-font.js`, там же разбор SVG-шрифтов и JHF, проверка «контурный» и компактный JSON). Будущее извлечение средних линий из TTF/OTF должно лишь выдать тот же объект.

**Пересборка встроенных шрифтов** (после обновления `vendor/hershey/`, `vendor/newstroke/` или `vendor/ems-fonts/`): `node tools/build_fonts.js` пишет `src/app/text/fonts/*.json` теми же разборщиками ядра; `node tools/build_fonts.js --check` только сравнивает (его запускает тест, забытая пересборка роняет набор).

#### Строки интерфейса

Словари — плоские модули `src/i18n/en.js`, `ru.js`, `es.js`, `de.js`, `fr.js` со стабильными точечными ключами (`print.upload`); значение — строка с `{параметрами}` или формы множественного числа (выбираются `Intl.PluralRules` по параметру `count`; в строке есть все формы, которые возвращают правила языка: `en`/`de` — `{ one, other }`, `es`/`fr` — `{ one, many, other }`, `ru` — `{ one, few, many, other }`). `t(key, params)`: нет ключа в текущем языке — берётся английский, нет и там — сам ключ. Числа в тексте форматирует `fmtNumber` (`Intl.NumberFormat`: «1.5» / «1,5»); в G-code и полях ввода — всегда точка. `tests/i18n.test.js` проверяет, что у всех языков те же ключи и параметры `{name}`, что в `en`, что у строк с формами множественного числа есть все формы языка, что все `t('…')` из `src` есть в каждом словаре, что в остальных словарях не осталось предложений по-английски (допускается не больше двух) и что в `src` не осталось кириллицы вне словарей.

Переключение в шапке работает **сразу, без перезагрузки страницы** (`createLanguageControl` в `src/app/lang.js`): выбор сохраняется, язык включается, статическая разметка переводится (`translateStatic`), а представления перестраиваются на месте (`src/app/ui/tab-host.js` снимает и заново монтирует каждую вкладку; индикатор и переключатель в шапке создаются заново). Сервисы не пересоздаются — состояние (рисунок, настройки, профили), транспорт, поток принтера, мониторы связи и калибровки, память прошивки и пределов — как и модели вкладок: вкладка SVG хранит загруженный файл, вкладка «Фото» — свою модель в `src/app/photo/photo-model.js` (изображение, слои, параметры, идущие в воркерах расчёты, которые завершаются уже в новом представлении), вкладка «Печать» — журнал, имя файла, «переезды» и шаг пульта; активная вкладка и масштаб предпросмотра тоже остаются. Тексты, которые бывают в схемах, константах и реестре, вычисляются при обращении (геттеры), поэтому не «застывают» на языке загрузки модуля.

**Новая строка**: добавить ключ во все словари (`en.js`, `ru.js`, `es.js`, `de.js`, `fr.js`, одинаковые параметры), в коде — `t('ключ', { параметр })`. Тесты, проверяющие русские тексты, подключают `tests/helpers/ru.js` (фиксирует `ru`).

**Подсказки к кнопкам.** Все кнопки создаются `button({ label, hint, onclick })` из `src/app/ui/dom.js`; `tests/buttons.test.js` проверяет, что других `h('button'` нет и ключ каждой подсказки есть в `en` и `ru`.

### Как добавить транспорт, авторизацию, хранилище

- **Транспорт**: объект с методами `configured, test, upload, job, pause, cancel, command` (см. `src/transport/transport.js`); ошибки — `TransportError`. Выбор реализации — в `src/app/main.js`.
- **Авторизация OctoPrint**: объект `{ init(http), prepare(request), recover(error, attempt), describe(error) }`; прогнать `tests/contract/auth.contract.js` для новой стратегии.
- **Хранилище**: объект `{ load(key), save(key, obj) }` (асинхронные), см. `LocalStorageStore` и `ServerStore`. Отказ записи — исключение с понятным текстом: приложение оставляет значение в памяти и показывает «Не удалось сохранить настройки».
- **Проверка перед отправкой**: функция `(ctx) => Promise<{ level: 'ok'|'confirm'|'block', message }>`; добавить в `preflight` в `main.js`.
- **Смена пера между слоями**: хук `beforeLayer(layer, index) => string[]` в `generateGcode`.

### Разработка плагина

```sh
tools/dev_octoprint.sh               # .venv + OctoPrint 1.11 + плагин (editable) + Virtual Printer, порт 5001, данные в .octoprint-dev
tools/test_plugin.sh                 # тесты плагина: общий .venv (создаётся один раз), работает и из git worktree
```

При первом запуске завершить мастер настройки в браузере (первый пользователь). Приложение копируется в плагин при каждом запуске скрипта; после правок в `src/` перезапустить скрипт (или `python3 tools/build_plugin.py --no-zip`).

API: `GET/PUT /plugin/plotter/api/profiles`, `PUT|DELETE …/profiles/<id>` (с ревизией `rev`; устаревшая — 409), `PUT …/profiles/active`; прежний `…/api/settings/profile` читает и пишет значения активного профиля.

### Проверка с OctoPrint (Virtual Printer)

Вручную: включить Virtual Printer в OctoPrint, подключить его, в приложении «Проверить связь» → загрузить SVG → «Загрузить в OctoPrint» (файл появился в Files) → «Отправить и печатать» (задание дошло до конца) → на новом задании «Пауза / продолжить» и «Отмена» (после отмены отправляется подъём пера).
