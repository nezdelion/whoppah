# Neptune Plotter

[English version](README.md)

Веб-приложение для пен-плоттера на Elegoo Neptune 3 Pro (Marlin) под управлением OctoPrint 1.11:
рисунок (сейчас SVG) → раскладка на листе → G-code для пера → скачивание или отправка в OctoPrint.

Чистый JavaScript (ES modules), без сборки и без npm-зависимостей.

## Запуск

```sh
cd plotter
python3 -m http.server 8000
```

Открыть <http://localhost:8000/>. С `file://` не работает (ES modules), нужен http-сервер. Firefox и Chromium последних версий.

## Настройка OctoPrint

1. В OctoPrint: Settings → API → включить **Enable Cross Origin Resource Sharing (CORS)**.
2. Там же взять **API key** (Settings → API → Application Keys или глобальный ключ).
3. В приложении, вкладка «Печать» → «Подключение»: адрес (`http://localhost:5000` для OctoPrint на этой же машине, по умолчанию; `http://octopi.local` для OctoPi на Raspberry Pi) и ключ; кнопка «Проверить связь».

Без адреса и ключа кнопки отправки неактивны, скачивание G-code работает. Ключ хранится только в localStorage браузера и не попадает в файл экспорта настроек.

## Язык интерфейса

Языки: английский (`en`, запасной) и русский (`ru`). Словари — плоские модули `src/i18n/en.js` и `ru.js` со стабильными точечными ключами (`print.upload`); значение — строка с `{параметрами}` или формы множественного числа `{ one, few, many, other }` (выбираются `Intl.PluralRules` по параметру `count`). `t(key, params)`: нет ключа в текущем языке — берётся английский, нет и там — сам ключ. Числа в тексте форматирует `fmtNumber` (`Intl.NumberFormat`: «1.5» / «1,5»); в G-code и полях ввода — всегда точка. `tests/i18n.test.js` проверяет, что наборы ключей и параметры `{name}` в `en` и `ru` совпадают, что все `t('…')` из `src` есть в словаре и что в `src` не осталось кириллицы вне словаря.

Какой язык включить (`src/i18n/detect.js`, `src/app/lang.js`), по убыванию приоритета:

1. явный выбор в переключателе языка в шапке страницы (Авто / English / Русский, на всех вкладках, в standalone и в плагине), хранится в `localStorage` (`neptune-plotter.lang`);
2. плагин: язык интерфейса текущего пользователя OctoPrint — `language` в динамическом `env.json` (пользовательская настройка `interface.language`, иначе общий `appearance.defaultLanguage`; «_default» значит «не выбран»);
3. `navigator.languages`: первый поддерживаемый (`ru*` → русский, `en*` → английский);
4. иначе английский (в том числе для неподдерживаемого языка OctoPrint, например `de`, — тогда смотрится язык браузера).

Язык выбирается при запуске, до построения интерфейса. Переключение в шапке работает **сразу, без перезагрузки страницы** (`createLanguageControl` в `src/app/lang.js`): выбор сохраняется, язык включается, статическая разметка переводится (`translateStatic`), а представления перестраиваются на месте (`src/app/ui/tab-host.js` снимает и заново монтирует каждую вкладку; индикатор и переключатель в шапке создаются заново). Сервисы не пересоздаются — состояние (рисунок, настройки, профили), транспорт, поток принтера, мониторы связи и калибровки, память прошивки и пределов — как и модели вкладок: вкладка SVG хранит загруженный файл, вкладка «Фото» — свою модель в `src/app/photo/photo-model.js` (изображение, слои, параметры, идущие в воркерах расчёты, которые завершаются уже в новом представлении), вкладка «Печать» — журнал, имя файла, «переезды» и шаг пульта; активная вкладка и масштаб предпросмотра тоже остаются. Уже показанные сообщения пересчитываются на новом языке; тексты, полученные раньше от ядра или OctoPrint (предупреждения импорта, журнал, подробности связи), остаются на прежнем языке, пока не появятся заново. Тексты, которые бывают в схемах, константах и реестре, вычисляются при обращении (геттеры), поэтому не «застывают» на языке загрузки модуля. Тексты сервера плагина (Python) остаются английскими: приложение показывает их только как подробности ошибки.

**Новая строка**: добавить ключ в оба словаря (в `en.js` и `ru.js`, одинаковые параметры), в коде — `t('ключ', { параметр })`. Тесты, проверяющие русские тексты, подключают `tests/helpers/ru.js` (фиксирует `ru`).

## Настройки

Все координаты в приложении — **положение головы** (сопла), как на экране OctoPrint; перо смещено относительно него, и приложение учитывает смещение через область пера и угол листа.

**Первая настройка (визард).** Карточка «Готовность к печати» сверху вкладки «Печать» показывает, что должно быть задано: связь (только standalone), область пера, угол листа, касание — готово / не задано / проверить, с кнопкой «Настроить» у пункта и «Пройти настройку» для всего визарда. Визард — модальный диалог по шагам, каждое изменение сохраняется сразу, закрыть можно на любом шаге:

1. **Связь** (standalone): адрес OctoPrint и ключ API, индикатор, «Проверить связь».
2. **Область пера**: профиль машины (принтер + держатель пера) и где кончик пера может рисовать — одним из двух способов (ниже).
3. **Лист**: формат и ориентация; положите лист на стол, затем либо «Подвести перо в угол области» (перо зависает над ближним левым углом области пера — подвиньте угол листа под кончик пера), либо подведите перо пультом в угол листа; затем «Угол листа здесь». «Перо не достаёт до угла листа» хранит смещение пера от угла для такого случая.
4. **Касание**: опускайте Z шагами, пока перо не коснётся бумаги, «Касание здесь»; ширина пера.
5. **Проверка**: список готовности, «Перо вверх», «Обвести рамку» (когда рисунок загружен).

На шагах с перемещением головы есть пульт (шаг 0.1/1/10 мм, X±/Y±/Z±) и защита «Home не выполнен» с кнопкой «Home уже сделан». Без источника положения (нет потока плагина) шаги показывают только поля для чисел.

**Область пера** (активный профиль). Два способа, выбираются переключателем; оба заполняют один и тот же прямоугольник стола профиля:
- **Смещение пера от сопла** `dx, dy` (правее / дальше от себя — положительно; перо ближе к себе, чем сопло, — отрицательный `dy`): стол в координатах головы — номинальный стол (по умолчанию 235×235 мм), сдвинутый на −смещение, дальний угол «по номиналу». Введите числа или подведите кончик пера в любой угол стола, до которого оно достаёт, выберите этот угол и нажмите «Перо здесь»: смещение = угол − положение головы. Пример: перо на 35 мм правее сопла, пределы X-4…234 — перо достаёт 204 мм по X.
- **Крайние положения пера**: ближнее левое и дальнее правое положение кончика пера над столом — «Взять текущее» или числа; хранятся как измеренные углы.
Редактор показывает «Перо достаёт: W × H мм», карту (стол, пределы осей, область пера, лист) и «Перейти» в углы области для проверки на глаз. **Область печати** = пределы осей ∩ стол; область не задана — пределы осей, а проверки «перо на столе» пропускаются с пометкой. Версии координат у стола нет (хоминг не делает его устаревшим).

Раскладка панели настроек:

- Карточка **«Готовность к печати»**, затем **«Задание»** (каждый раз): формат бумаги (свои форматы сохраняются), ориентация, отступ, выравнивание, поворот, «как есть в мм», «Ограничить областью печати»; свёрнутые **«Оптимизация»** (допуски упрощения и слияния) и **«Калибровка — значения»** (угол листа и касание числами, с датой).
- **«Принтер»** (свёрнуто, редко): **профили машины**, редактор области пера, высоты пера как смещения от касания, скорости, пределы осей, ширина пера, `G28`/`M84`, подключение (standalone), экспорт/импорт настроек. Состояние сворачивания запоминается в браузере.
- Карточка калибровки справа: предупреждение «могла устареть» с «Угол верен» / «Касание верно», пульт и «Настроить…».

**Профили машины.** Профиль — «принтер + держатель пера»: до 20 именованных профилей, один активный; «Новый» (значения по умолчанию), «Дублировать», «Переименовать», «Удалить» (не последний; при удалении активного активным становится соседний). Раскладка, G-code, проверки, пульт и оценка времени берут активный профиль; параметры задания, угол листа и касание в профиль не входят и при смене не меняются. Угол и касание зависят от держателя, поэтому после смены профиля обе части помечаются «калибровка могла устареть (сменён профиль машины)», и печать просит подтверждения — до нового захвата, ввода или «Угол верен» / «Касание верно» (возврат к прежнему профилю — снова актуально). Единственный профиль прежних версий при первом запуске становится профилем «Neptune 3 Pro» (standalone — в браузере, плагин — на сервере); старые данные не удаляются.

**«Ограничить областью печати»** (задание, по умолчанию включено, отмечено ⚠): рисунок вписывается (масштаб и выравнивание) в (поле листа − отступы) ∩ (область печати, переведённая в координаты листа через угол); сам лист может выходить за область (предупреждение по сторонам). Выключено: вписывание в лист, как раньше. Если поле минус отступы целиком в области печати, G-code одинаков при включённой и выключенной опции. Перед отправкой рисунок проверяется по области печати независимо от опции: выход за предел оси или за край стола (по сторонам, в мм) — подтверждение.

**«Точка» и «Перейти».** Любая точка в координатах головы (угол листа, положения пера) — один и тот же элемент: X/Y, «Взять текущее», «Перейти». «Перейти» читает положение, поднимает перо до высоты старта, если оно ниже (или неизвестно), переводит по X/Y и при актуальном касании опускает до касание + зазор; точка вне пределов осей — отказ. Защиты и права — как у пульта.

Экспорт/импорт настроек файлом — внизу панели настроек: версия формата 2 (все профили с активным, калибровка, задание, пресеты); файл версии 1 (один профиль) отклоняется с сообщением «старый формат файла настроек не поддерживается». Настройки старой страницы (`neptune-plotter.settings`) переносятся один раз при первом запуске.

**Подсказки к кнопкам.** У каждой кнопки короткая подсказка (ключ словаря `<область>.<кнопка>.hint`): на компьютере — при наведении, на сенсорном экране — знак «?» рядом с кнопкой (текст под кнопкой). Все кнопки создаются `button({ label, hint, onclick })` из `src/app/ui/dom.js`; `tests/buttons.test.js` проверяет, что других `h('button'` нет и ключ каждой подсказки есть в `en` и `ru`.

## Плагин OctoPrint

Приложение можно отдавать самим OctoPrint 1.11 полноэкранной страницей `/plugin/plotter/`: без отдельного сервера, API-ключа и CORS, с общими для всех устройств настройками. Standalone-режим (выше) продолжает работать параллельно.

**Режимы.** При запуске приложение читает `env.json` рядом со страницей: статический `{"mode":"standalone"}` — REST с API-ключом и настройки в браузере; динамический `env.json` плагина — авторизация сессией OctoPrint (заголовок `X-CSRF-Token`) и настройки на сервере. Код вкладок и ядра от режима не зависит; в режиме плагина адрес и ключ не показываются, в шапке есть ссылка «← OctoPrint».

**Установка.**

```sh
python3 tools/build_plugin.py        # копирует index.html, src/, vendor/ в пакет плагина и собирает dist/OctoPrint-Plotter-<версия>.zip
```

OctoPrint → Settings → Plugin Manager → «Get More…» → «… from an uploaded file» → выбрать zip → перезапустить OctoPrint. В верхней панели появится ссылка «Plotter». Обновление — тем же способом с новым zip (после перезапуска браузер сам перепроверяет файлы: страница и статика отдаются с `Cache-Control: no-cache` и ETag). Удаление — в Plugin Manager. Версия — `octoprint-plugin/octoprint_plotter/_version.py` (или `--version X.Y.Z` при сборке).

**Права и хранение настроек.**

- Страница и служебные адреса доступны только вошедшим пользователям (без входа — переход на вход OctoPrint и возврат в приложение).
- Профили машины (с активным) и калибровка общие для всех; параметры задания и пресеты — свои у каждого пользователя. Смена профиля на другом устройстве подхватывается при следующем опросе (5 с).
- Любая запись профилей — значения, стол, создание, дублирование, переименование, удаление **и выбор активного** — требует права **«Plotter: Machine profile»** (`PLUGIN_PLOTTER_MACHINE_PROFILE`): по умолчанию есть у группы администраторов; выдаётся в Settings → Access Control (пользователю или группе). Без права профили показываются только для чтения. API: `GET/PUT /plugin/plotter/api/profiles`, `PUT|DELETE …/profiles/<id>` (с ревизией `rev`; устаревшая — 409), `PUT …/profiles/active`; прежний `…/api/settings/profile` читает и пишет значения активного профиля.
- Запись калибровки требует штатного права OctoPrint **Control**. Печать, загрузка и пауза проверяются правами OctoPrint (Print, File Upload, Control); при отказе показывается «нет права: …».
- Раздел не больше 1 МБ; неизвестные разделы сервер отклоняет.

**Захват калибровки и пульт.** Подведите перо штатной вкладкой Control, затем на вкладке «Печать» нажмите «Угол здесь» (с учётом смещения пера от угла листа) или «Касание здесь»; положение читается командами `M118`/`M400`/`M114` (во время печати недоступно). «Угол верен» / «Касание верно» подтверждают часть без изменения значений. После хоминга (`G28`) или переподключения принтера приложение показывает «калибровка могла устареть», а печать требует подтверждения. Нужны право Control и прошивка, отвечающая на `M118`.

Те же кнопки есть и в standalone, когда на связи поток принтера: калибровка лежит в браузере, версии координат — в памяти потока, поэтому после перезагрузки страницы обе части считаются устаревшими до нового захвата или «Угол верен» / «Касание верно». Пока поток не видел `G28` (с момента подключения к принтеру; Home по осям учитывается отдельно для XY и Z), захват и пульт отключены с подсказкой «Home не выполнен — сделайте Home до установки пера»; `G28` приложение само не шлёт; если Home сделан до открытия страницы (с пером `G28` опасен), кнопка «Home уже сделан» с подтверждением снимает защиту до ближайшего переподключения, версии координат она не меняет. Пульт перемещения (X±/Y±/Z±, шаг 0.1/1/10 мм, оба режима) читает положение перед каждым шагом, не выходит за пределы осей профиля, а Z — ниже касания больше чем на 2 мм; если стол измерен, а перо может быть опущено (Z неизвестен или ниже касание + зазор), X/Y не выходят из области печати, а за краем стола Z не ниже касание + зазор.

**Настройки прошивки (standalone, поток на связи).** «Прочитать настройки прошивки» (раздел «Подключение») шлёт `M503` и разбирает `M201`/`M203`/`M204`/`M205`/`M420`: сводка, предупреждения (подачи профиля выше `M203`, затухание сетки ниже касания), «Заполнить ускорения профиля…» по подтверждению. Результат хранится только в памяти, до обрыва потока; пока он есть, оценка времени срезает подачи по `M203` и стартует с рывка `M205` (пометка «с учётом прошивки»). В плагине потока нет — там не доступно.

**Перенос настроек из standalone.** В standalone: «Экспорт в файл» внизу панели настроек; в плагине: «Импорт из файла…». Профили и калибровка при отсутствии прав пропускаются с сообщением, остальное импортируется. Если на сервере у пользователя ещё нет настроек, а в `localStorage` того же адреса (host:port) есть настройки standalone, приложение предложит перенести их само.

**Разработка.**

```sh
tools/dev_octoprint.sh               # .venv + OctoPrint 1.11 + плагин (editable) + Virtual Printer, порт 5001, данные в .octoprint-dev
tools/test_plugin.sh                 # тесты плагина: общий .venv (создаётся один раз), работает и из git worktree
```

При первом запуске завершить мастер настройки в браузере (первый пользователь). Приложение копируется в плагин при каждом запуске скрипта; после правок в `src/` перезапустить скрипт (или `python3 tools/build_plugin.py --no-zip`). За обратным прокси с префиксом (`X-Script-Name`) адреса строятся от `script_root`, приложение открывается по `https://host/octoprint/plugin/plotter/`.

## Структура и правило зависимостей

```
index.html                точка входа
src/core/                 чистые функции над Drawing: geometry, svg-import, svg-export, optimize, layout, gcode, profile, profiles, bed, jog, pipeline
src/transport/            интерфейс Transport, OctoPrint REST (fetch), авторизация по ключу и сессией (плагин)
src/storage/              SettingsStore (localStorage, сервер OctoPrint), файл настроек
src/i18n/                 локализация: t(key, params), словари en.js / ru.js, выбор языка (detect.js); ничего не импортирует
src/styles/               стили «изображение → линии»: реестр, runner (воркеры), адаптер plotterfun, собственные стили (own/)
vendor/plotterfun/        сторонний код plotterfun (копия без правок), версия — в vendor/plotterfun/UPSTREAM
octoprint-plugin/         Python-плагин OctoPrint (страница, env.json, API настроек, право)
tools/                    build_plugin.py (сборка zip), dev_octoprint.sh (локальный OctoPrint)
src/app/                  оболочка: state, вкладки, формы, превью, сервис печати
tests/                    node --test
```

`i18n` → ничего (и не трогает DOM); `core`, `transport`, `storage`, `styles`, `app` могут импортировать `i18n` (core возвращает готовые тексты ошибок и предупреждений); `core` → только `core` и `i18n`; `transport`, `storage` — так же только свой слой и `i18n`; `styles` → `core` (`styles/tone.js` и `styles/own/*` — только `core`, без DOM); `app` → всё. Правило проверяет `tests/deps.test.js`.
Все модули обмениваются моделью `Drawing` (слои полилиний, плоские массивы `[x0, y0, x1, y1, ...]`, система координат «документ» или «машина»).

Порядок обработки (`core/pipeline.js`): импорт → раскладка (мм) → упрощение → сортировка/слияние → G-code.

## Как добавить источник рисунка

Создать `src/app/tabs/<имя>-tab.js`, экспортировать фабрику объекта `{ id, title, mount(el, ctx), unmount(), dispose?() }` и добавить её в список вкладок в `src/app/main.js`. `mount` может вызываться повторно после `unmount` с тем же `ctx` (смена языка перестраивает представления): модель (загруженные данные, результаты, идущая работа) хранится в фабрике, а не в представлении; `unmount` снимает только подписки и обработчики представления, `dispose` (необязательный) разбирает и модель. Источник получает только `ctx`:

- `ctx.emit(drawing)` — выдать рисунок (`createDrawing` из `core/drawing.js`, координаты «документ»);
- `ctx.presets.load()/save(obj)` — своя область сохранения;
- `ctx.printParams.get()/subscribe(fn)` — только чтение: поле, отступ, поворот, ширина пера.

Вкладка «Печать» не меняется. Промежуточный результат помечается `meta.partial = { reasons: [...] }`.

### Вкладка «Фото» и стили

Вкладка «Фото» (`src/app/tabs/photo-tab.js`) — обычный источник: изображение → стек слоёв-стилей → `ctx.emit(drawing)`, каждый видимый слой становится слоем рисунка. Расчёт идёт в воркерах (`src/styles/runner.js`), новый запуск слоя отменяет прежний. Слой получает статус «готово» только по достоверному сигналу завершения; для стилей plotterfun он строится обёрткой `src/styles/plotterfun-host.js` по манифесту `src/styles/plotterfun-completion.json` (модель исполнения каждого стиля: `sync`, `async-handler`, `timer-chain`, `none`). Манифест действует только для коммита из первой строки `vendor/plotterfun/UPSTREAM`; после обновления vendor запустить `python3 tools/audit_plotterfun.py` — непроверенные стили получат `none` (результат остаётся промежуточным, печать — с подтверждением).

Добавить свой стиль: чистая функция `(gray, w, h, params) => lines` в `src/styles/own/`, запись в `src/styles/own/worker.js` (таблица `IMPL`) и дескриптор в `src/styles/registry.js`.

## Как добавить транспорт, авторизацию, хранилище

- **Транспорт**: объект с методами `configured, test, upload, job, pause, cancel, command` (см. `src/transport/transport.js`); ошибки — `TransportError`. Выбор реализации — в `src/app/main.js`.
- **Авторизация OctoPrint**: объект `{ init(http), prepare(request), recover(error, attempt), describe(error) }`; прогнать `tests/contract/auth.contract.js` для новой стратегии.
- **Хранилище**: объект `{ load(key), save(key, obj) }` (асинхронные), см. `LocalStorageStore` и `ServerStore`. Отказ записи — исключение с понятным текстом: приложение оставляет значение в памяти и показывает «Не удалось сохранить настройки».
- **Проверка перед отправкой**: функция `(ctx) => Promise<{ level: 'ok'|'confirm'|'block', message }>`; добавить в `preflight` в `main.js`.
- **Смена пера между слоями**: хук `beforeLayer(layer, index) => string[]` в `generateGcode`.

## Проверка с OctoPrint (Virtual Printer)

Вручную: включить Virtual Printer в OctoPrint, подключить его, в приложении «Проверить связь» → загрузить SVG → «Загрузить в OctoPrint» (файл появился в Files) → «Отправить и печатать» (задание дошло до конца) → на новом задании «Пауза / продолжить» и «Отмена» (после отмены отправляется подъём пера).
