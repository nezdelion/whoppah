# Whoppah — OctoPrint pen plotter plugin

[English version](README.md)

> — Dad, can we have a pen plotter at home?<br>
> — **W**e **H**ave **O**ur **P**en **P**lotter **A**t **H**ome (WHOPPAH)

Веб-приложение для пен-плоттера на основе 3D-принтера под управлением OctoPrint.
Протестировано на Elegoo Neptune 3 Pro (Marlin) и OctoPrint 1.11.

Рисунок (SVG, фото в одном из стилей линий или текст) → раскладка на листе → G-code для пера → скачивание или отправка в OctoPrint.

Чистый JavaScript (ES modules), без сборки и без npm-зависимостей.

## Запуск

```sh
cd plotter
python3 -m http.server 8000
```

Открыть <http://localhost:8000/>. С `file://` не работает (ES modules), нужен http-сервер. Firefox и Chromium последних версий.

### GitHub Pages

Рабочая версия: **<https://nezdelion.github.io/whoppah/>** — публикуется из `main` через CI после прохождения тестов.

Standalone-приложение — это просто статические файлы, поэтому оно работает и с GitHub Pages (или любого статического хостинга) без локального сервера:

- HTTPS-страница может обращаться к OctoPrint по `http://localhost:5000`: localhost браузеры считают доверенным (свежий Chrome может один раз спросить разрешение на доступ к локальной сети).
- OctoPrint по адресу в локальной сети по обычному HTTP (`http://octopi.local`, `http://192.168.…`) блокируется как смешанное содержимое (mixed content): включите HTTPS у OctoPrint или используйте [плагин OctoPrint](#плагин-octoprint).
- CORS в OctoPrint должен разрешать адрес Pages (`https://<user>.github.io`), см. [Настройка OctoPrint](#настройка-octoprint).
- Настройки хранятся в localStorage этого адреса, отдельно от `http://localhost:8000`: переносите их экспортом/импортом настроек. Ключ API остаётся в браузере (в файл экспорта он не попадает, его вводят заново).

## Плагин OctoPrint

OctoPrint 1.11 может сам отдавать приложение полноэкранной страницей `/plugin/plotter/`: без отдельного сервера, API-ключа и CORS, настройки общие для всех устройств. Standalone-режим продолжает работать параллельно.

**Установка.**

Готовый zip — в [релизах](https://github.com/nezdelion/whoppah/releases) или в артефактах [сборок CI](https://github.com/nezdelion/whoppah/actions/workflows/ci.yml?query=branch%3Amain+is%3Asuccess) (запуск → Artifacts; нужен вход в GitHub, скачанный архив содержит zip плагина). Или собрать самому:

```sh
python3 tools/build_plugin.py        # собирает dist/OctoPrint-Plotter-<версия>.zip
```

OctoPrint → Settings → Plugin Manager → «Get More…» → «… from an uploaded file» → zip → перезапустить OctoPrint. В верхней панели появится ссылка «Plotter». Обновление — тем же способом новым zip, удаление — в Plugin Manager. Каждый коммит даёт версию выше (см. [Разработка плагина](#разработка-плагина)).

**Права.**

- Открыть приложение могут только вошедшие пользователи (остальных отправляет на вход OctoPrint).
- Профили машины и калибровка общие для всех; параметры задания и пресеты — свои у каждого.
- Изменение профилей, включая выбор активного, требует права **«Plotter: Machine profile»** (по умолчанию у администраторов; выдаётся в Settings → Access Control). Без него профили только для чтения.
- Запись калибровки требует **Control**; печать, загрузка и пауза — Print, File Upload и Control.

**Захват калибровки.** Подведите перо пультом или вкладкой Control в OctoPrint и нажмите на вкладке «Печать» «Угол здесь» или «Касание здесь» (положение читается через `M118`/`M400`/`M114`; не во время печати). «Угол верен» / «Касание верно» подтверждают без изменения значений. После хоминга, переподключения принтера или смены профиля калибровка помечается «могла устареть», и печать просит подтверждения. В standalone те же кнопки есть, когда на связи поток принтера; после перезагрузки страницы калибровка считается устаревшей.

**Защита от Home.** Само приложение `G28` не шлёт: хоминг с установленным пером может его сломать. Пока поток не видел `G28`, захват и пульт отключены с подсказкой «Home не выполнен — сделайте Home до установки пера». «Home (G28)» делает хоминг после подтверждения, что перо снято или поднято; «Home уже сделан» снимает защиту до следующего переподключения.

**Пульт.** X±/Y±/Z±, шаг 0.1/1/10 мм. Не выходит за пределы осей профиля, не опускается ниже касания больше чем на 2 мм, а пока перо может быть опущено, X/Y остаются в области печати.

**Настройки прошивки** (standalone с потоком). «Прочитать настройки прошивки» шлёт `M503`: сводка, предупреждения (подачи профиля выше `M203`, затухание сетки ниже касания) и «Заполнить ускорения профиля…». Оценка времени после этого учитывает пределы прошивки.

**Перенос настроек из standalone.** «Экспорт в файл» в standalone, «Импорт из файла…» в плагине. Если на сервере ваших настроек ещё нет, а в браузере есть настройки standalone для того же host:port, приложение предложит перенести их.

Работает за обратным прокси с префиксом (`X-Script-Name`), например `https://host/octoprint/plugin/plotter/`.

## Настройка OctoPrint

Только для standalone:

1. OctoPrint: Settings → API → включить **Enable Cross Origin Resource Sharing (CORS)**, скопировать **API key**.
2. Приложение: вкладка «Печать» → «Подключение»: адрес (`http://localhost:5000` по умолчанию, `http://octopi.local` для OctoPi) и ключ → «Проверить связь».

Без них работает только скачивание G-code. Ключ остаётся в браузере и не попадает в экспорт настроек.

## Настройки и калибровка

Все координаты — **положение головы (сопла)**, как показывает OctoPrint. Смещение пера учитывается через область пера и угол листа.

**Мастер настройки.** Карточка «Готовность к печати» на вкладке «Печать» показывает, чего не хватает (связь, область пера, угол листа, касание), с кнопкой «Настроить» у пункта и «Пройти настройку» для всего. Шаги, каждый сохраняется сразу:

1. **Связь** (standalone): адрес, ключ API, «Проверить связь».
2. **Область пера**: профиль машины и где перо может рисовать (ниже).
3. **Лист**: формат и ориентация. «Подвести перо в угол области» и подвиньте угол листа под кончик, или подведите перо пультом в угол листа; затем «Угол листа здесь». Если перо не достаёт до угла — «Перо не достаёт до угла листа».
4. **Касание**: опускайте Z, пока перо не коснётся бумаги, «Касание здесь»; ширина пера.
5. **Проверка**: «Перо вверх», «Обвести рамку».

**Область пера** — два способа:

- **Смещение пера от сопла** `dx, dy` (вправо / от себя — положительно). Введите числа или поставьте кончик пера в угол стола и нажмите «Перо здесь». Пример: перо на 35 мм правее сопла при пределах X -4…234 достаёт 204 мм по X.
- **Крайние положения пера**: ближнее левое и дальнее правое положение кончика.

Редактор показывает охват («Перо достаёт: W × H мм») и карту; «Перейти» ведёт в углы области для проверки на глаз. **Область печати** = пределы осей ∩ стол.

**Панель настроек.**

- **«Задание»** (каждый раз): формат бумаги, ориентация, отступ, выравнивание, поворот, «Как есть в мм», «Ограничить областью печати»; свёрнутые **«Оптимизация»** и **«Калибровка — значения»**.
- **«Принтер»** (редко): профили машины, область пера, высоты пера от касания, скорости, пределы осей, ширина пера, `G28`/`M84`, подключение, экспорт/импорт настроек.

**Профили машины.** Профиль = принтер + держатель пера; до 20, один активный. Параметры задания, угол листа и касание в профиль не входят.

**«Ограничить областью печати»** (по умолчанию включено): рисунок вписывается в поле листа минус отступы, обрезанное по области печати. Независимо от опции, если рисунок выходит за предел оси или край стола, перед отправкой нужно подтверждение.

**«Перейти»** при необходимости сначала поднимает перо, переводит по X/Y и при актуальном касании опускает до касание + зазор.

**Файл настроек.** Экспорт/импорт внизу панели: профили, калибровка, задание, пресеты (формат 2; файлы формата 1 отклоняются). Настройки прежних версий переносятся при первом запуске.

У каждой кнопки есть подсказка: на компьютере — при наведении, на сенсорном экране — за «?».

## Вкладки

### Вкладка «SVG»

Перетащите SVG-файл на вкладку или нажмите, чтобы выбрать. Показывает число линий и точек и размер в мм, если он задан в файле. Текст и растровые изображения пропускаются с предупреждением — текст сначала переведите в кривые. Рисунок сразу уходит на вкладку «Печать».

### Вкладка «Фото» и стили

Превращает фото в линии: стек слоёв-стилей, каждый видимый слой становится слоем рисунка. Большая часть стилей — из [plotterfun](https://github.com/mitxela/plotterfun); его непроверенные стили дают промежуточный результат, и печать просит подтверждения.

**Кадр.** «Кадр» показывает всё фото с рамкой: углы и стороны тянут для размера, внутри — для сдвига. «Рамка» — свободная или по полю рисунка. «Сбросить кадр» возвращает всё фото. Кадр принадлежит фото и в пресеты не сохраняется.

**«Растворить фон»** (сила, размер, мягкость; 0 — выключено): вне эллипса в середине изображение уходит в белый, как в овальном гравированном портрете. Сохраняется в пресете вкладки.

#### Волнистые линии

Параллельные линии под заданным углом и с шагом (мм); каждая — волна, у которой с тёмностью растёт амплитуда и/или частота. В тёмном — 3 или 5 слитых проходов, в светлом ниже порога обрыва линия прерывается. «Сдвигать каждую вторую линию на полпериода» ставит соседей в противофазу. Пресеты: тонкие волны, классика, крупно.

«Соединять концы штрихом до» («Оптимизация») ставьте 0 или чуть больше шага линий, чтобы соединить змейку вдоль краёв (быстрее, но переходы видны).

#### Гравюра

Линии следуют форме изображения, как в портрете на банкноте.

- **Тон**: «Автоуровни» растягивают блёклое фото; «Локальный контраст» вытягивает полутона на ярком фоне.
- **Направление**: линии идут вдоль линий равного тона, повёрнутых на «Поворот к изофотам». «Сглаживание поля» (мм) — размер форм, за которыми идут линии; «Мелкие детали» — насколько их изгибают глаза, нос, волосы. Плоские участки и текстура («Порог плоских областей», «Упрощать фон») переходят к «Базовому углу»; «Следовать форме» 0 % даёт прямые линии.
- **Шаг и толщина**: «Шаг в тёмном/светлом» × «Базовый шаг»; ниже «Обрыва в светлом» линии нет. В тёмном линии толще, с «Тонкими концами штрихов», не больше «Макс. заливки в тенях»; в самых тёмных местах — «Перекрёстный слой». Штрихи короче «Мин. длины штриха» отбрасываются.
- **Пресеты**: портрет, банкнота, эскиз.

Если шаг слишком мал, слой останавливается с «Слишком много линий — увеличьте шаг». Начинайте с «Соединять концы штрихом до» = 0.

Значения по умолчанию обоих стилей — предварительные до проверки на бумаге.

### Вкладка «Текст»

Пишет текст **однолинейным шрифтом**: каждая буква — несколько штрихов по средней линии, проходимых один раз, как линером. Задайте высоту заглавных (мм), межбуквенный и межстрочный интервал, наклон, выравнивание, ширину переноса (0 — без переноса) и «Как от руки». На «Печать» рисунок уходит по «В печать»; он в мм, и «Как есть в мм» включается, чтобы буквы сохранили заданную высоту. Текст печатается в порядке чтения.

**«Как от руки»** (0–100 %) добавляет небольшой случайный разброс размера, наклона и базовой линии. Тот же текст, параметры и зерно дают тот же результат; «Новый вариант» выбирает другое зерно. Пресеты: аккуратно, естественно, торопливо.

**Шрифты**: Hershey Script, EMS Felix, EMS Allure (рукописные) и NewStroke (технический). Во всех латиница, цифры и русский. Рукописные берут кириллицу из NewStroke, поэтому она печатный курсив, а не пропись. Недостающие знаки берутся из NewStroke или заменяются (в крайнем случае «?» с предупреждением).

**Свои шрифты.** «Добавить шрифт…» принимает однолинейные SVG-шрифты (как из Hershey Text в Inkscape) и Hershey `.jhf`. Контурные шрифты (TTF/OTF/WOFF, SVG из замкнутых контуров) отклоняются. Хранятся у пользователя: на сервере в плагине (до 1 МБ), в браузере в standalone. В файл настроек не входят.

## Язык интерфейса

Английский, русский, испанский, немецкий, французский. Выбирается по порядку: переключатель в шапке → язык пользователя OctoPrint (плагин) → язык браузера → английский. Переключение срабатывает сразу, без перезагрузки; рисунок, настройки, слои фото и журнал сохраняются. Сообщения сервера плагина остаются английскими.

## Разработка

Дальше — для тех, кто меняет само приложение.

### Структура и правило зависимостей

```
index.html                точка входа
src/core/                 чистые функции над Drawing: geometry, svg-import, svg-export, optimize, layout, gcode, profile, profiles, bed, jog, pipeline
src/transport/            интерфейс Transport, OctoPrint REST (fetch), авторизация по ключу и сессией (плагин)
src/storage/              SettingsStore (localStorage, сервер OctoPrint), файл настроек
src/i18n/                 локализация: t(key, params), словари en.js / ru.js, выбор языка (detect.js); ничего не импортирует
src/styles/               стили «изображение → линии»: реестр, runner (воркеры), драйвер стилей, адаптер plotterfun, собственные стили (own/, помощники own/kit/)
vendor/plotterfun/        сторонний код plotterfun (копия без правок), версия — в vendor/plotterfun/UPSTREAM
vendor/hershey/, vendor/newstroke/, vendor/ems-fonts/   однолинейные шрифты вкладки «Текст» (оригиналы без правок, LICENSE, UPSTREAM)
octoprint-plugin/         Python-плагин OctoPrint (страница, env.json, API настроек, право)
tools/                    build_plugin.py (сборка zip), dev_octoprint.sh (локальный OctoPrint), build_fonts.js (встроенные шрифты вкладки «Текст»)
src/app/                  оболочка: state, вкладки, формы, превью, сервис печати
tests/                    node --test
```

`i18n` → ничего (и не трогает DOM); `core`, `transport`, `storage`, `styles`, `app` могут импортировать `i18n` (core возвращает готовые тексты ошибок и предупреждений); `core` → только `core` и `i18n`; `transport`, `storage` — так же только свой слой и `i18n`; `styles` → `core` (`styles/tone.js` и `styles/own/*` вместе с `own/kit/*`, кроме `own/worker.js`, — только `core`, `i18n`, `tone.js` и друг друга, без DOM); `app` → всё. Правило проверяет `tests/deps.test.js`.
Все модули обмениваются моделью `Drawing` (слои полилиний, плоские массивы `[x0, y0, x1, y1, ...]`, система координат «документ» или «машина»).

Порядок обработки (`core/pipeline.js`): импорт → раскладка (мм) → упрощение → сортировка/слияние → G-code.

### Тесты

```sh
npm test        # или: node --test
```

Обёртка стилей plotterfun (`tests/plotterfun-host.test.js`): по умолчанию быстрый набор (по стилю на каждую модель исполнения, случай «стиль падает сам», данные после final), весь `node --test` около 7 с. Полный перебор 23 стилей по вариантам параметров и двум изображениям (около 2 минут): `PLOTTERFUN_SWEEP=1 node --test tests/plotterfun-host.test.js`; `PLOTTERFUN_FULL=1` дополнительно ставит тишину 1 с после final и 5 с для эталона.

Тесты плагина: `tools/test_plugin.sh` (аргументы уходят в pytest). Venv `.venv` в основной копии создаётся при первом запуске (OctoPrint 1.11 + pytest) и дальше переиспользуется, в том числе из worktree; тот же venv берёт `tools/dev_octoprint.sh`.

Эталонный G-code для паритета со старой реализацией: `tests/fixtures/*.gcode`; пересоздаётся `node tests/tools/gen-golden.js` (использует копию старого ядра `tests/tools/legacy-core.cjs`).

### Как добавить источник рисунка

Создать `src/app/tabs/<имя>-tab.js`, экспортировать фабрику объекта `{ id, title, mount(el, ctx), unmount(), dispose?() }` и добавить её в список вкладок в `src/app/main.js`. `mount` может вызываться повторно после `unmount` с тем же `ctx` (смена языка перестраивает представления): модель (загруженные данные, результаты, идущая работа) хранится в фабрике, а не в представлении; `unmount` снимает только подписки и обработчики представления, `dispose` (необязательный) разбирает и модель. Источник получает только `ctx`:

- `ctx.emit(drawing)` — выдать рисунок (`createDrawing` из `core/drawing.js`, координаты «документ»);
- `ctx.presets.load()/save(obj)` — своя область сохранения;
- `ctx.printParams.get()/subscribe(fn)` — только чтение: поле, отступ, поворот, ширина пера.

Вкладка «Печать» не меняется. Промежуточный результат помечается `meta.partial = { reasons: [...] }`.

#### Вкладка «Фото»: устройство

Вкладка «Фото» (`src/app/tabs/photo-tab.js`) — обычный источник: изображение → стек слоёв-стилей → `ctx.emit(drawing)`, каждый видимый слой становится слоем рисунка. Расчёт идёт в воркерах (`src/styles/runner.js`), новый запуск слоя отменяет прежний. Слой получает статус «готово» только по достоверному сигналу завершения; для стилей plotterfun он строится обёрткой `src/styles/plotterfun-host.js` по манифесту `src/styles/plotterfun-completion.json` (модель исполнения каждого стиля: `sync`, `async-handler`, `timer-chain`, `none`). Манифест действует только для коммита из первой строки `vendor/plotterfun/UPSTREAM`; после обновления vendor запустить `python3 tools/audit_plotterfun.py` — непроверенные стили получат `none` (результат остаётся промежуточным, печать — с подтверждением).

**Кадр и растворение.** Геометрия рамки — `src/app/photo/crop.js` (чистые функции). Кадр получает всё рабочее разрешение (`rasterize(decoded, workingSize, crop)`), поэтому `mmPerPx` и проверка плотности считаются по нему. Кадр живёт в модели вкладки (переживает смену языка и пресет) и не сохраняется: пресет восстанавливается без фото. «Растворить фон» — `applyVignette` в `src/styles/prep.js` (smoothstep, к рабочему изображению до любого стиля), в пресете вкладки — поле `vignette`.

**Алгоритм гравюры.** Тон: автоуровни по перцентилям, CLAHE (8 плиток по длинной стороне). Поле направлений: сглаженный структурный тензор яркости в двух масштабах (мелкие детали — в 1/3 «Сглаживания поля»), резкие перепады ограничены; поле зависит только от автоуровней, не от остальных настроек тона. Линии: равномерно разнесённые линии тока (Jobard–Lefer) от центра, сходятся не ближе половины шага; толщина — 3/5 проходов (`thicken`), не больше расстояния до ближайшей линии. Штрихи короче трёх шагов тоже отбрасываются; размещение останавливается на пределе числа точек.

Тексты статуса собственных стилей могут содержать числа: воркер шлёт прогресс как `{ key, params }` (например, `{ key: 'styles.progress.waves', params: { percent: 40 } }` → «Волнистые линии 40%»), обычные строки — ключи словаря или тексты plotterfun.

**Этапы гравюры.** Все параметры живые: ползунки толщины и «Макс. заливка в тенях» пересчитывают только последний этап, ползунки перекрёстного слоя не трогают основные линии, базовый угол, мелкие детали и упрощение фона переиспользуют тензор, локальный контраст — поле. Стиль может приложить такое замечание («Слишком много линий — увеличьте шаг») к итоговому результату: `yield { note: { key, params } }`.

#### Добавить свой стиль

Простой путь: чистая функция `(gray, w, h, params, paper) => lines` (линии — полилинии `Float64Array` в px рабочего изображения) в `src/styles/own/`, запись `'own:<имя>': plain(fn, 'styles.progress.<ключ>')` в таблице `IMPL` файла `src/styles/own/worker.js` и дескриптор в `src/styles/registry.js` (так сделан `crosshatch`).

Стиль с живыми ползунками — генератор этапов (пример — `src/styles/own/waves.js`):

```js
function* mySteps({ gray, w, h, params, paper, cache }) {
  const dark = stage(cache, 'tone', [params.invert, params.gamma], () => toDarkness(gray, params));       // этап с кэшем
  const geo = yield* stageGen(cache, 'geo', [dark, params.spacing], function* () { /* yield progressOf(KEY, f) */ });
  return stage(cache, 'finish', [geo, params.passes], () => /* Float64Array[] */);
}
export const myStyle = (gray, w, h, params, paper) => runToEnd(mySteps({ gray, w, h, params, paper, cache: createCache() }));
```

В `IMPL` он регистрируется как `staged(mySteps)`. Воркер исполняет его драйвером `src/styles/style-driver.js`: квантами по 30 мс (между ними обрабатываются сообщения), прогресс не чаще 200 мс, `yield { partial: lines }` — промежуточный результат, возвращаемое значение — финальный. Параметры с `live: true` идут в работающий воркер; побеждает последнее значение (текущий генератор бросается на ближайшей границе кванта и запускается заново с тем же кэшем этапов, поэтому пересчитываются только этапы с изменившимися зависимостями; брошенный этап ничего не сохраняет). Зависимости этапа сравниваются через `===`; чтобы связать этапы, передайте значение предыдущего этапа как зависимость. Результат должен зависеть только от изображения, параметров и `paper` — живое изменение даёт то же, что новый запуск (это проверяют тесты).

Поля дескриптора сверх `id, name, group, origin, params, adapter, createWorker, spacing`:

- `usesPaper: true` — размерные параметры заданы в мм на бумаге. Запуск получает `paper = { mmPerPx, penWidthMm }` (`mmPerPx` — масштаб «px рабочего изображения → мм», тот же, что в проверке плотности: поле минус отступы с учётом поворота; без параметров печати 0.25 мм/px и перо 0.5 мм); вкладка пересчитывает слой, когда поле, отступ, поворот или ширина пера меняют этот масштаб. Масштаб предполагает, что рисунок заполняет изображение (раскладка вписывает охватывающий прямоугольник рисунка), «Ограничить областью печати» пока не учитывается. `spacing(params, image, paper)` возвращает шаг линий в px для проверки плотности.
- `presets: [{ id, label, params }]` — пресеты стиля: в карточке слоя появляется строка «Пресет» (значения по умолчанию, поверх — значения пресета; слой перезапускается); значения сохраняются в пресете вкладки как обычно.
- у параметра `select` может быть `optionLabel(value)` — показываемый текст варианта (само значение от языка не зависит).

Общие чистые помощники в `src/styles/own/kit/` (без DOM, работают в node-тестах): `params.js` (`paramFactory(prefix)` — ленивые подписи `t('<prefix>.param.<key>')` и подписи вариантов `t('<prefix>.<key>.<value>')`; `presetFactory(prefix)` — `t('<prefix>.preset.<id>')`; `presetValues`, `matchPreset`), `paper.js` (`DEFAULT_PAPER`, `paperOf`, `mmToPx`, `samePaper`), `lines.js` (`lineFamily` — параллельные линии через изображение, обрезанные им, `clipLine`, `arcLengths`, `dropShort`), `stroke.js` (`thicknessProfile`, `thicken` — толщина линии 1/3/5 близкими проходами внутри одной непрерывной полилинии с сужающимися «линзами», `endTaperPx` — тонкие концы штриха), `order.js` (`orientChain`, `orientGroups` — направления штрихов для коротких переходов, змейка для семейства линий), `stages.js` (`createCache`, `stage`, `stageGen`, `runToEnd`, `progressOf`). Также `toDarkness` (с `gamma`), `boxBlur`, `sampleBilinear` из `src/styles/tone.js` и `simplifyLine` из `src/core/optimize.js`. Все тексты — через `t()`: добавьте ключи `<prefix>.param.*`, вариантов и пресетов в `en.js` и `ru.js`, а стиль — в `OWN_PREFIX` в `tests/i18n.test.js`.

#### Вкладка «Текст»: интерфейс шрифта и пересборка

Интерфейс шрифта: вёрстка (`src/core/text-layout.js`) знает только `StrokeFont` — `{ id, name, capHeight, xHeight, glyphs: Map<кодовая точка, { advance, lines }> }` в единицах шрифта, базовая линия y = 0, Y вниз (`src/core/stroke-font.js`, там же разбор SVG-шрифтов и JHF, проверка «контурный» и компактный JSON). Будущее извлечение средних линий из TTF/OTF должно лишь выдать тот же объект.

**Пересборка встроенных шрифтов** (после обновления `vendor/hershey/`, `vendor/newstroke/` или `vendor/ems-fonts/`): `node tools/build_fonts.js` пишет `src/app/text/fonts/*.json` теми же разборщиками ядра; `node tools/build_fonts.js --check` только сравнивает (его запускает тест, забытая пересборка роняет набор).

#### Строки интерфейса

Словари — плоские модули `src/i18n/en.js`, `ru.js`, `es.js`, `de.js`, `fr.js` со стабильными точечными ключами (`print.upload`); значение — строка с `{параметрами}` или формы множественного числа (выбираются `Intl.PluralRules` по параметру `count`; в строке есть все формы, которые возвращают правила языка: `en`/`de` — `{ one, other }`, `es`/`fr` — `{ one, many, other }`, `ru` — `{ one, few, many, other }`). `t(key, params)`: нет ключа в текущем языке — берётся английский, нет и там — сам ключ. Числа в тексте форматирует `fmtNumber` (`Intl.NumberFormat`: «1.5» / «1,5»); в G-code и полях ввода — всегда точка. `tests/i18n.test.js` проверяет, что у всех языков те же ключи и параметры `{name}`, что в `en`, что у строк с формами множественного числа есть все формы языка, что все `t('…')` из `src` есть в каждом словаре, что в остальных словарях не осталось предложений по-английски (допускается не больше двух) и что в `src` не осталось кириллицы вне словарей.

**Переключение языка на лету** (`createLanguageControl` в `src/app/lang.js`): сохраняет выбор, переводит статическую разметку (`translateStatic`) и перемонтирует представление каждой вкладки (`src/app/ui/tab-host.js`). Сервисы (состояние, транспорт, поток принтера, мониторы) и модели вкладок не пересоздаются, поэтому вкладка хранит данные в модели, а не в представлении (см. [Как добавить источник рисунка](#как-добавить-источник-рисунка)). Тексты в схемах, константах и реестре — геттеры, поэтому не «застывают» на языке загрузки.

**Выбор языка** (`src/i18n/detect.js`): сохранённый выбор `whoppah.lang` → `language` из `env.json` плагина (пользовательский `interface.language`, иначе `appearance.defaultLanguage`; `_default` — не выбран) → `navigator.languages` по основной части кода → английский. Тексты, полученные раньше от ядра или OctoPrint, остаются на прежнем языке, пока не появятся заново.

**Новая строка**: добавить ключ во все словари (`en.js`, `ru.js`, `es.js`, `de.js`, `fr.js`, одинаковые параметры), в коде — `t('ключ', { параметр })`. Тесты, проверяющие русские тексты, подключают `tests/helpers/ru.js` (фиксирует `ru`).

**Подсказки к кнопкам.** Все кнопки создаются `button({ label, hint, onclick })` из `src/app/ui/dom.js`; `tests/buttons.test.js` проверяет, что других `h('button'` нет и ключ каждой подсказки есть в `en` и `ru`.

### Как добавить транспорт, авторизацию, хранилище

- **Транспорт**: объект с методами `configured, test, upload, job, pause, cancel, command` (см. `src/transport/transport.js`); ошибки — `TransportError`. Выбор реализации — в `src/app/main.js`.
- **Авторизация OctoPrint**: объект `{ init(http), prepare(request), recover(error, attempt), describe(error) }`; прогнать `tests/contract/auth.contract.js` для новой стратегии.
- **Хранилище**: объект `{ load(key), save(key, obj) }` (асинхронные), см. `LocalStorageStore` и `ServerStore`. Отказ записи — исключение с понятным текстом: приложение оставляет значение в памяти и показывает «Не удалось сохранить настройки».
- **Проверка перед отправкой**: функция `(ctx) => Promise<{ level: 'ok'|'confirm'|'block', message }>`; добавить в `preflight` в `main.js`.
- **Смена пера между слоями**: хук `beforeLayer(layer, index) => string[]` в `generateGcode`.

### Разработка плагина

**Режимы.** При запуске приложение читает `env.json` рядом со страницей: статический `{"mode":"standalone"}` — REST с API-ключом, настройки в браузере; динамический `env.json` плагина — сессия OctoPrint (`X-CSRF-Token`), настройки на сервере, язык пользователя. Код вкладок и ядра от режима не зависит.

**Версия.** MAJOR.MINOR — из `octoprint-plugin/octoprint_plotter/_version.py`, PATCH — число коммитов с момента смены MAJOR.MINOR; незакоммиченные правки добавляют `.post<время UTC>`; `--version X.Y.Z` задаёт явно. Сборка не меняет файлы в репозитории. Страница и статика отдаются с `Cache-Control: no-cache` и ETag.

**Хранение на сервере.** Раздел настроек не больше 1 МБ, неизвестные разделы отклоняются; смену профиля другие устройства видят при следующем опросе (5 с).

**CI (GitHub Actions, `.github/workflows/ci.yml`).** Каждый push в `main` и каждый pull request запускает `npm test` и тесты плагина, затем собирает zip плагина (скачивается из запуска как артефакт). Тег `v*` (например, `git tag v0.2.12 && git push origin v0.2.12`) дополнительно публикует релиз GitHub с zip; ставится в OctoPrint через Plugin Manager → «… from URL» по ссылке на файл релиза (публичный репозиторий) или скачиванием.

```sh
tools/dev_octoprint.sh               # .venv + OctoPrint 1.11 + плагин (editable) + Virtual Printer, порт 5001, данные в .octoprint-dev
tools/test_plugin.sh                 # тесты плагина: общий .venv (создаётся один раз), работает и из git worktree
```

При первом запуске завершить мастер настройки в браузере (первый пользователь). Приложение копируется в плагин при каждом запуске скрипта; после правок в `src/` перезапустить скрипт (или `python3 tools/build_plugin.py --no-zip`).

API: `GET/PUT /plugin/plotter/api/profiles`, `PUT|DELETE …/profiles/<id>` (с ревизией `rev`; устаревшая — 409), `PUT …/profiles/active`; прежний `…/api/settings/profile` читает и пишет значения активного профиля.

### Проверка с OctoPrint (Virtual Printer)

Вручную: включить Virtual Printer в OctoPrint, подключить его, в приложении «Проверить связь» → загрузить SVG → «Загрузить в OctoPrint» (файл появился в Files) → «Отправить и печатать» (задание дошло до конца) → на новом задании «Пауза / продолжить» и «Отмена» (после отмены отправляется подъём пера).
